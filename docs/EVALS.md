# Evaluating the AI tutor

Lotse lets a language model rate exam writing, write exam tasks and give hints. Each of those can fail quietly: a rater that is always a little too kind, a task with two right answers, a hint that is really the answer. This page describes how each one is measured, shows the latest numbers, and says what they do not prove.

## What is measured

| Job | Check | Where it runs |
|---|---|---|
| **Rating telc writing** (criteria I–III, bands A–D) | Agreement with reference bands on a golden set: exact and ±1 band, quadratic weighted kappa (QWK), error in telc points, agreement on "B2 reached". Planted mistakes found (recall). Share of reported mistakes that quote the text (precision of `QuotedErrors`). Prompt-injection cases in which no criterion got an A. | `tools/Lotse.Evals`, by hand with a key. The rule-based baseline runs without a key. |
| **Socratic hints** | Share of AI hints that would have given the answer away. The app's leak filter discards those, so a learner never sees one. Share of hints phrased as a question. | `tools/Lotse.Evals --hints N`. |
| **Hint ladder** (no AI) | No rung of any of the ~2,250 seed exercises contains an accepted answer. | `HintLadderTests`, in CI on every push. |
| **Generated telc tasks** | Format rules, no copying (six-word overlap with every task of the part ≤ 15 %), a critic model's review, a human decision. The review page reports the acceptance rate and how often the critic agrees with the human. | Live on `/telc/entwuerfe`. Pipeline logic tested in `TelcPipelineTests`. |
| **The harness itself** | The golden set is valid (tasks exist, planted snippets are in the text, codes are in the catalogue). The metrics compute correctly on hand-checked examples. | `EvalTests`, in CI. |

Three raters run on the same harness. They differ only in where the bands come from:

- **The AI tutor exactly as the app calls it.** Same task text, same system prompt. Then the same form caps from `TelcWritingCheck`: no A in criterion II without subject line, salutation and closing; a linear list of points gets at most C.
- **Rule-based (without AI).** What the app does without a key: B in every criterion, then the same caps. Mistakes come from the rule-based analyzer.
- **Always B.** The trivial rater. A real rater has to beat it to be worth its cost.

## How to run it

```bash
dotnet run --project tools/Lotse.Evals
```

```bash
GROQ_API_KEY=... dotnet run --project tools/Lotse.Evals -- --preset groq --hints 40 --write
```

`--preset` takes any preset of the settings page: `groq`, `anthropic`, `openrouter`, `ollama`, `mistral`, `deepseek` or `openai`. `--model` overrides the preset's model. `--write` stores the run in `evals/results/` and regenerates the table above. Without `--write` nothing on disk changes.

Twelve texts take about a minute on Groq. That is a dozen requests, well inside the free tier.

## What these numbers do not prove

- **The reference bands are the author's**, given on telc's published criteria. They are not a licensed examiner's. The numbers measure agreement with one careful non-examiner, which is weaker than agreement with telc. The most valuable improvement is to have the twelve texts rated by a DaF teacher who examines telc B2, and to record that in each case's `rater` field.
- **Twelve cases is a small set.** It is meant to catch regressions (a prompt change, a model swap), not to certify a rater. With 36 criterion pairs, one band either way moves exact agreement by about three points.
- **Planted mistakes are a lower bound on recall.** The texts contain other mistakes too, and reporting those is not penalised.
- **The texts were written for the set.** They are not real learner texts and contain no telc material. Real learner texts are messier, especially transcripts from the oral exam, which this set does not cover yet.
